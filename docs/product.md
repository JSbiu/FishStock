# FishStock 产品定义

## 产品定位

FishStock 是面向开发者的轻量 VS Code 自选行情工具。它只解决一个问题：编码过程中无需离开编辑器，就能安静地看一眼少量关注股票、指数、ETF 或商品期货的价格和涨跌状态。

产品关键词是：低干扰、本地优先、透明、克制。

## 目标用户

- 日常在 VS Code 或兼容编辑器中工作，希望偶尔查看行情的开发者
- 只需要维护小型自选列表，不需要投资组合管理的人
- 重视隐私，不希望为了基础行情注册产品账户或上传自选数据的人

## 核心场景

1. 用户在 Activity Bar 打开 FishStock，通过同级 `Stock`、`Fund`、`Futures` 和 `Holdings` 视图快速扫视自选与本地持仓。
2. 用户在状态栏看到一个自选条目的简短行情，几秒后自动轮播到下一个。
3. 用户按名称、简称或代码搜索个股、指数或境内 ETF，确认匹配结果后直接加入对应品类的目标分组；科创板、北交所、市场指数和交易所 ETF 不因品种类型被遗漏，其他自选变更也只保存在本机。
4. 用户发现行情刷新失败、市场休市或数据已经过期时，能够理解当前展示是否可信，但不会被连续弹窗打断。
5. 用户将鼠标悬停在个股上，查看日内价格、成交、基础估值和上市板块，无需打开新页面。
6. 用户按品种名称或合约代码搜索国内商品期货，在同一次预览中选择主连或当前有效月份合约。
7. 用户首次打开时可从预置的股票、指数、ETF 示例和五个商品期货主连行情开始，并可分别清空或恢复三个自选品类的默认数据；持仓保持空白。
8. 用户为 A 股、港股或境内交易所 ETF 记录数量与平均成本，并在不合并币种的前提下查看当前市值、浮动盈亏和收益率。

## 0.3.x MVP

- A 股、港股及市场指数的名称、拼音简称和代码搜索与展示；覆盖科创板，并支持北交所证券简称、新旧代码及 `920` 代码直查
- Activity Bar 入口与原生 Tree View
- 自选条目的增删、跨组移动与组内排序
- 分组的增删、重命名和折叠
- 自动刷新、手动刷新、缓存、过期判断和请求合并
- 一个状态栏项目，轮播并可点击打开自选
- 原生悬浮行情卡；个股展示日内价格、成交、PE(TTM)、总市值与上市板块，期货展示昨结、成交量、持仓量与交易所
- VS Code 本机持久化
- 股票和期货独立的本机自选数据，以及各自的清空和恢复默认能力
- 可替换行情提供器接口
- 腾讯 A 股与港股行情提供器
- A 股和港股市场指数行情
- 国内商品期货主连和有效月份合约行情
- 涨跌颜色习惯配置

## 非目标

第一阶段明确不做：

- 场外基金、ETF 联接基金、LOF、港股 ETF、加密货币和外汇
- 新闻、公告、舆情和 AI 分析
- 交易流水、已实现收益、费用税费、分红、资产曲线、多账户和完整投资组合管理
- K 线、盘口和复杂图表
- 提醒、Webhook、自动交易和券商下单
- 付费功能、订阅、FishStock 账户和 FishStock 自有服务器
- 遥测或用户行为分析

## 体验原则

- 默认安静：后台刷新不弹成功通知，失败只改变当前状态。
- 一眼可懂：状态使用“休市”“刷新超时”“等待当日行情”“暂不可用”等直接文字。
- 界面收敛：行情概览坚持原生 Tree View，只有需要批量表格编辑的持仓管理使用单一编辑器 Webview；侧边栏最多两层，状态栏只有一个项目。
- 尊重主题：使用 VS Code ThemeColor，不设置醒目的状态栏背景色。
- 不假装实时：休市、延时或过期数据必须明确标识。

## 成功标准

0.3.x 的成功不是行情覆盖面，而是完成稳定、可检查的本地行情闭环：

- 可以在 Extension Development Host 中稳定激活。
- 用户可完成自选、分组、排序、刷新、清空和默认数据恢复。
- 数据源可以在不改动 UI 和存储模块的情况下替换。
- 编译、lint、核心单元测试和本地 VSIX 打包可重复通过。

## 0.4.x 可信与顺手

0.4 系列不做新品类，把"看一眼"这个动作做深：

- 交易日历：内置 A 股 2024–2026 年与港股 2025–2026 年交易所节假日，休市状态可信；非交易日停止自动轮询，更安静。
- 行情跳转：点击自选条目在浏览器打开东方财富、腾讯行情或新浪期货详情页，深度信息交给外部页面，不违背轻量定位。
- 视图展示方式：每个视图独立的默认顺序、按涨跌幅排序和涨跌筛选，只影响展示，不改变自选底层顺序。
- 质量与反馈：用户可随时反馈，必要时主动复制脱敏诊断信息；固定验收、Extension Host 冒烟和 VSIX 发布门槛由维护者独立完成。

## 0.4 已定决策

- 数据源策略：继续使用腾讯、新浪公开网页端点，接受字段与访问策略的变更风险，不引入账户、授权或费用。
- 稳定性优先级：先做交易日历；备用行情源和完整期货交易规则（夜盘、各品种到期规则）留到后续版本。
- 品类边界：0.4 不增加基金或美股；基金若增加，坚持独立同级 View，并单独评估数据授权要求。

## 0.5.x 境内 ETF

0.5 系列新增独立 `Fund` View，首版只覆盖腾讯搜索和行情端点可识别的沪深交易所 ETF：

- ETF 与股票代码格式相同，但使用独立本地存储、命令、分组和视图状态，不混入 Stock。
- 搜索只接受供应商类型为 `ETF` 的沪深结果，明确排除 `KJ` 场外基金、ETF 联接基金、LOF 和其他基金类型。
- 行情复用腾讯价格字段、交易日历、缓存、过期判断和访问拒绝退避；状态栏继续保持一个项目轮播全部品类。
- 不增加净值估算、基金份额、跟踪误差、成分股、申购赎回或投资组合功能。

## 0.5.x 公开预览

0.5.1 起通过 VS Code Marketplace 的 Preview 与 Pre-Release 通道公开试用，目标是用真实环境反馈验证安装、升级、跨平台和行情可用性，不借发布阶段扩张产品范围：

- 发布者使用可承载多个产品的 `jsbiu` 身份，FishStock 保持独立产品名称。
- 源代码采用 MIT License；免费核心不妨碍未来将独立增值能力或服务采用其他商业模式。
- 继续保持无 FishStock 账户、无自有服务器、无遥测，并公开说明必要的第三方行情请求。
- 腾讯和新浪网页行情没有面向 FishStock 的正式接口保证。预览版接受这一已知限制，以访问拒绝退避、过期状态、脱敏诊断和支持文档降低影响，不承诺所有地区和网络环境可用。
- 0.5.1 通过公开预览收集安装和兼容性反馈；满足发布清单后，使用不同的修订版本号转为稳定通道。

## 0.5.2 状态栏轮播体验

- 作为公开预览阶段的首个稳定通道版本；`Preview` 继续表示产品成熟度，不再要求普通用户选择 Pre-Release。
- 用户以现有自选分组为最小单位，跨 Stock、Fund 与 Futures 选择哪些分组参与状态栏轮播，不逐只维护另一份证券列表。
- 默认所有分组参与，新建分组默认参与；选择使用稳定的品类与分组 ID 保存，重命名不影响结果。
- 轮播顺序继续遵循品类、分组与分组内条目的现有顺序，不自动交错或随机播放。
- 全部取消代表主动关闭轮播；状态栏保留低调入口，便于重新选择。

## 0.5.3 首次打开性能

- 本地自选数据与 Tree View 完成装配后立即结束扩展激活，不等待腾讯或新浪行情请求。
- Stock、Fund 与 Futures 先展示已有分组和条目；价格、涨跌与行情状态由首次后台刷新随后更新。
- 行情源响应慢、超时或返回错误时，只影响行情更新，不再阻塞本地分组出现。

## 0.5.4 本地加载性能

- 已存在且格式有效的 Stock、Fund 与 Futures 自选只读取和校验，不在每次激活时重复持久化。
- 首次创建默认数据或修复无效数据时仍必须完成一次持久化，日常打开不承担这部分写入延迟。
- 任一 View 从折叠状态变为可见时立即通知 VS Code 读取当前内存树，不依赖行情刷新事件唤醒视图。

## 0.5.5 首开性能

- FishStock 启动后预初始化 Stock、Fund 与 Futures 的原生 Tree View，把 VS Code 的首次 View 初始化放到用户查看之前完成。
- 三个 View 在窗口重载后保持展开；启动时若正在使用其他侧边栏，预初始化完成后自动切回，避免长期抢占界面。
- View 隐藏期间合并行情引起的树更新，首次显示直接使用当前内存缓存；重复的分组折叠状态不再触发本地存储写入。

## 0.5.6 启动边界修复

- 撤销启动阶段主动 `reveal` 三个 View 的方案，FishStock 不改变 VS Code 原本选择的活动侧边栏。
- 全新工作区首次进入 FishStock 时使用清单声明的默认展开布局；已有工作区继续使用 VS Code 保存的用户布局。
- Stock、Fund 与 Futures 始终独立折叠和展开，不在首次展开某个 View 时联动其余 View。

## 0.6.0 交易时段与行情状态可靠性

- A 股、港股与国内商品期货使用独立时段模型，覆盖集合竞价、连续交易、午休/盘间休息、收盘竞价、港股半日市和节假日。
- 国内商品期货按品种登记夜盘边界，支持 23:00、次日 01:00、次日 02:30 与仅日盘四类，并把周五夜盘归入下周一交易日。
- 自动刷新只请求当前正在交易的条目；在开盘、休息和收盘边界立即更新状态并补取相关条目。手动刷新始终允许获取最近行情，也可以绕过自动退避。
- `live` 只表示当前交易中且数据新鲜；`closed` 表示有有效最近行情但当前休市；`stale` 表示缓存不满足当前交易时段可靠性；`error` 只表示没有有效行情可展示。
- 新增期货只开放时段规则已收录的国内商品品种。升级前已保存但尚未收录的品种不会删除，日盘按国内商品期货通用时段处理，可能存在夜盘时保守显示“交易时段未收录”。
- 不改变 `globalState` 的自选结构，不增加迁移、账户、遥测或服务端依赖。

## 0.6.1 行情新鲜度修订

- 行情源时间表示最近一笔行情的时间，最近成功获取时间表示客户端确实取得了有效响应；两者分开记录，价格或行情时间不变化不等于请求失败。
- `live` 允许过期阈值内的短暂刷新失败并显示警告；只有持续没有成功获取超过阈值才转为“刷新超时”。
- 行情有效性以交易日为边界，同一交易日的上午行情可跨午休、下午和收盘继续展示，期货夜盘与次日日盘共享所属交易日边界。
- `stale` 必须给出刷新超时、交易日行情缺失、行情时间异常或时段未收录之一；脱敏诊断只统计原因，不包含代码或自选名称。
- 不改变自动/手动刷新范围、交易时段规则或本地存储结构。

本里程碑不包含持仓 View、持仓成本、资产、盈亏和收益展示；这些能力仍属于后续产品决策，不进入 0.6.x。

## 0.7.0 本地持仓与收益

- 新增与 Stock、Fund、Futures 同级的 `Holdings` View，首版只接受 A 股、港股和境内交易所 ETF；不纳入指数和期货。
- 每条持仓只保存规范化代码、名称、品类、正整数数量和正数平均成本。持仓仓库默认空白，使用独立 `globalState` 键，不读取、迁移或改写既有自选数据。
- 持仓行情复用现有 Stock/Fund 提供器、缓存、交易时段与 `live`、`closed`、`stale`、`error` 状态，不增加第四个行情源或独立网络缓存。
- 浮动盈亏按“`(现价 - 平均成本) × 数量`”计算，收益率按“`浮动盈亏 ÷ 成本市值`”计算；人民币与港币分别分组和汇总，不做汇率换算。
- `closed` 和 `stale` 的有效价格仍参与计算并明确显示状态；`error` 或缺少有效价格时不展示估算收益。所有结果均不包含费用、税费、分红和公司行动影响。
- 状态栏保持一个项目，现有行情轮播为默认模式；用户可切换为逐条持仓盈亏轮播并在当前 VS Code Profile 中保存选择。
- 脱敏诊断只统计持仓条目数、币种分布和行情状态，不包含证券代码、数量、成本、市值或盈亏。

0.7.0 暂不包含期货持仓、交易记录、已实现收益、费用税费、分红、汇率换算、多账户、资产曲线、导入导出、云同步和下单能力。

## 0.7.1 持仓批量管理

- Holdings Tree View 继续作为只读概览；新增单例编辑器管理器承载搜索、批量添加、内联修改、批量删除、行情预览和统一保存。
- 用户可以连续搜索多个关键词，在每轮结果中多选标的；新标的进入同一草稿表格后再填写数量与平均成本，不为每只标的重复打开输入框。
- 现有持仓的数量与成本可在表格中同时修改。删除只先作用于草稿，点击“保存全部”后才与其他修改一起生效。
- 扩展进程保留已确认搜索结果并重新校验全部草稿；页面不能写入未知标的。任一行无效或本地存储失败时整批拒绝，已加载的内存状态保持不变。
- 草稿未保存时关闭管理器，提供保存、继续编辑和放弃三种选择。页面隐藏后继续复用同一实例，不额外打开编辑器标签。
- Webview 使用严格 CSP、无外部资源和无直接网络访问；行情、搜索、跳转与存储继续通过扩展侧既有边界完成。

0.7.1 不增加导入导出、自由文本/JSON 编辑、交易流水、费用模型、汇率换算或电子表格公式。

## 0.7.2 持仓调仓

- 调仓入口只放在编辑器管理器中，与数量、平均成本的修改共用同一份草稿；Holdings Tree View 继续作为只读概览，不承担录入动作。
- 一行持仓可记录一次买入或卖出：加仓按数量加权摊薄平均成本，减仓只改数量且平均成本不变。平均成本按 4 位小数记录，减仓不重新摊薄成本。
- 减仓时提示本次已实现盈亏，但 FishStock 不保存、不汇总、不展示历史已实现收益；全部卖出的持仓在保存后从列表移除。
- 预览由扩展侧领域函数计算，Webview 不重复实现成本公式；输入非法或卖出超过持有数量时阻止应用，不产生半成品草稿。
- 不新增存储字段，不改动 `fishStock.holdings.v1` 结构，不需要数据迁移；调仓仍受现有“任一行无效则整批拒绝”约束，保存后才会写入本机。

0.7.2 不增加交易流水、分批建仓明细、先进先出或个别计价法、税费与手续费、撤销与历史回看，也不改变“不记录已实现收益”的产品边界。

## 0.7.3 持仓自选导入

- 持仓管理器的添加卡片新增「从自选股添加」页签，与搜索并列：可从股票与 ETF 自选中批量勾选标的，一次加入持仓草稿后统一填写数量与平均成本。
- 自选候选按持仓边界过滤，仅保留 A 股、港股与境内 ETF，自动排除指数、期货与美股；已在持仓或草稿中的条目标记「已在表格中」并禁止重复添加。
- 候选品类按来源仓库推导，与行情缓存保持一致；过滤逻辑抽为纯函数并配有单元测试，保存仍走既有整批校验。
- 不改动 `fishStock.holdings.v1` 结构，不需要数据迁移。

0.7.3 不增加自选与持仓的自动同步、双向联动或持仓导入导出。

## 0.7.4 当日盈亏与持仓视图

- 新增当日盈亏，按「行情归属交易日」判定可用性：盘中、午休与收盘后照常显示，盘前、周末与节假日显示 `—`。判定只看行情自带时间戳，不看刷新状态——刷新失败时只要数据仍属于当天就继续显示，避免数值在刷新抖动时反复跳变；缓存跨了交易日则必须退回 `—`，不把上一交易日的涨跌标成今日盈亏。
- 当日盈亏按当前持仓数量估算，未计入当日交易、佣金、税费与汇率换算。不单独提供当日盈亏比例：在没有当日调仓的前提下它恒等于涨跌幅，单列没有信息量。
- 展示覆盖 Holdings Tree View 条目与币种分组、悬浮卡，以及编辑器管理器的新增列与合计行。Tree View 一行的结构：个股是「股数 · 市值 · 浮盈(百分比) · 今日盈亏(百分比)」，币种分组是「市值 · 浮盈(百分比) · 今日盈亏(百分比)」。市值按万/亿压缩，盈亏保留完整金额，百分比只表示幅度、方向由金额的正负号表达，不重复币种单位。一行最多放四个数据点，再多就显乱。
- Holdings View 新增视图排序与筛选，命令入口与自选一致：默认顺序、盈利优先、亏损优先、仅看盈利、仅看亏损。**排序依据是相对成本的收益率，不是当日涨跌幅**，避免与新增的当日盈亏列混淆。
- 视图模式与自选共用 `fishStock.viewOptions.v1` 的 `holdings` 键；旧数据缺少该字段时回退为默认顺序，不需要迁移。筛选后为空的币种分组直接隐藏，不留空组。
- 股票与 ETF 自选为已在持仓的条目挂「持」角标（图标右上角的小徽标）。**不改文字颜色**：TreeItem 的文字颜色只能整条目设置，一旦用掉就没有通道再表达涨跌方向，而涨跌方向由条目左侧的箭头图标承载。匹配键为品类加代码，避免同一代码在股票自选与 ETF 自选之间误标；期货自选不参与。
- 编辑器管理器表格新增按币种的合计行，汇总市值、浮动盈亏、收益率与当日盈亏；未填全或没有行情的条目不计入，并在标签后标注待填写数量。

0.7.4 不增加表格列头排序、录入键盘流转、持仓导出与自选持仓双向联动。

## 0.7.6 持仓排序与手动顺序

- 排序提供五个维度：默认顺序、**浮动盈亏收益率 / 金额**、**今日盈亏收益率 / 金额**。除默认顺序外，再次选择同一项即切换升 / 降序，不需要额外的方向设置。
- 「默认顺序」即用户的手动顺序：可在持仓条目右键菜单上移 / 下移，顺序持久化；从未调整过就等于添加顺序。手动排序只在**同一币种分组内**生效，跨币种不参与。
- **不做持仓筛选**（0.7.4 的「仅看盈利 / 仅看亏损」已下掉）：在 Tree View 里藏掉一部分仓位会影响对整体配置的判断，而排序已能覆盖主要诉求。
- 非默认排序下手动顺序会被覆盖，此时「上移 / 下移」菜单项自动隐藏，避免点了没反应。
- 排序状态与自选的单一 mode 解耦，单独存 `holdingsSort` + `holdingsSortDesc`。

0.7.6 不增加跨币种拖拽、排序状态的常驻可见提示、按分组保存不同排序。

## 0.7.7 港币折算、停牌识别与换股取舍

- **港币折算**：配置 `fishStock.holdings.hkdToCnyRate`（如 `0.8557`）后，港币持仓的市值、浮动盈亏、当日盈亏按人民币展示，Tree View、悬浮卡与编辑器管理器三处一致。折算**只在展示层**做，领域数据始终按标的原币种存储，汇率变动不污染持久化数据；**百分比不受折算影响**——收益率与当日百分比都是相对值，汇率在分子分母里约掉了。
- **停牌识别**：行情源标记停牌时不再参与当日盈亏计算。停牌当日无成交、昨收与最新价相同，此前会被算成"今日 ±0"，与真正的平盘无法区分；现在描述行显示「停牌」、图标改用暂停样式、悬浮卡当日盈亏为 —。停牌优先于「刷新超时」判定。
- **数据声明**：悬浮卡与 README 标注行情来自第三方公开源、与券商对账可能存在差异、以券商为准。同花顺口径的「当日参考盈亏」含税费估算且港股按固定汇率折算，与 FishStock 天然对不上——这是口径差异，不是缺陷。
- **换股（吸收合并）不做专门功能**：持仓标的被合并后（如东兴证券 → 中金公司），由用户手动「添加新股 + 删除旧仓」完成，靠保持**成本金额一致**来延续浮动盈亏（新成本单价 = 原成本金额 ÷ 新股数）。理由：换股是低频事件，公告的比例表述不统一，且存在零股处理与分批到账，专用命令的边界情况多而收益低。

0.7.7 不增加换股命令、汇率自动获取、税费估算、停牌期间的替代估值。

## 0.7.8 收盘数据时机

- **收盘后 60 秒宽限刷新**：A 股最终收盘价在 15:00:00 收盘集合竞价落定后才由行情源发布。此前"一到收盘就停刷"会把 14:59:5x 的盘中价当成收盘价，收盘价与当日盈亏随之偏移。宽限期内仍按调度间隔刷新；同样覆盖午休与盘间断点，使上一段的收尾价格落定。
- 港币折算的操作方式（设置界面 / `settings.json`、留空还原、数值方向）写入 README，补上此前只描述了能力、没写操作步骤的缺口。

0.7.8 不增加盘后行情轮询、收盘价单独校时、按市场自定义宽限时长。

## 0.8.0 统一展示与跨币种折算

- **持仓不再按币种分组**：人民币与港币持仓合并为一列，排序与手动顺序都跨币种生效。此前分组是「汇率不可靠」前提下的稳妥做法（组内各自自洽），代价是排序不完整、手动顺序被组困住、两组数字要心算比较。用户判断这个日常不便超过汇率失真的风险，据此改造。
- **汇率从可选变为默认开启**：`fishStock.holdings.hkdToCnyRate` 默认 `0.9`——刻意取整数近似值，让它看起来就像占位值而不是精确值，提醒使用者按实际汇率调整。可在持仓管理页直接修改，并有「默认」按钮一键恢复。折算仍只在展示层发生，领域数据按原币种存储。
- **新增总计行**：置于列表末尾，汇总全部持仓（港币按当前汇率折人民币后合并）。这是本次**明确解开的边界**——`AGENTS.md` 原写「不做跨币种资产合计」。
- **港股条目挂「港」角标**：合并后 A 股与港股混排，两者交易时间与涨跌规则都不同，需要一眼可辨。停牌等状态继续走图标，不与角标争位（TreeItem 只有一个角标位）。
- **悬浮窗修正**：停牌状态此前只判 `quote.state`，而停牌时行情源照常返回有效价格、`state` 仍是 `live`，于是 Tree View 说「停牌」、悬浮卡说「开市」。现改为优先判 `quote.suspended`。
- **悬浮窗美化**：状态行与摘要行加主题图标，口径说明与数据来源声明分段，折算标注独立成行。tooltip 的文字颜色不可自定义，因此图标是唯一能表达语义差异的通道。

代价与取舍：汇率失真会静默影响港币条目的折算结果，故在悬浮卡上明确标注折算来源与数值；这是本方案的主要风险，接受它换取排序与汇总的一致性。

0.8.0 不增加自动汇率获取、汇率历史、按币种分别排序、跨币种资产曲线。

## 0.8.4 持仓展示与操作入口一致性修订

制定日期：2026-10-30。状态：计划，尚未实施；当前版本仍为 0.8.3。

目标：完成 0.8 系列的展示口径与操作入口收尾，让排序状态不隐藏已有操作、汇率只影响金额、停牌在各类界面保持一致，并让手动修改配置不会造成空白或错误显示。继续使用现有持仓结构、收益公式、行情缓存和单一 Webview，不扩展产品边界。

### 计划依据

- 0.8.3 已解决草稿保存、页面复用、搜索乱序和错误定位；本版不再重复修改这些已闭合路径，只处理其外围展示与入口。
- `HoldingsTreeProvider` 在非默认排序下把条目的 `contextValue` 改为 `fishStock.holdingSorted`，但扩展清单中的编辑、删除和行内编辑菜单仍只匹配 `fishStock.holding`。代码路径已确认：选择收益率或金额排序后，这些入口会随上移 / 下移一起消失；预期只隐藏上移 / 下移。
- 持仓悬浮卡和管理页目前会把港币单价、平均成本也换算成人民币，与 README、0.7.7 和架构文档中“汇率只换算市值、成本市值与盈亏金额”的约定不一致。单价来自行情或券商录入，不应被默认占位汇率改写。
- 持仓 Tree View、持仓悬浮卡和管理页已识别停牌，但普通行情悬浮卡、Stock/Fund/Futures Tree View 与状态栏仍可能把停牌显示为“开市”或普通实时状态。停牌应优先于 `live`、`closed`、`stale` 展示，复牌后恢复原状态。
- 汇率配置缺少统一的运行时归一化：手动在 `settings.json` 写入超出 `0.1–2` 的值时，部分展示仍可能折算；`treeViewFields` 只配置部分字段或被写成无效值时，也没有统一的默认合并与兜底。
- 2026-10-30 基线执行 `pnpm run check` 已通过，现有 236 个单元与回归测试全部成功。上述问题集中在展示契约、菜单声明和运行时配置校验，现有领域计算测试未覆盖。

### 实施范围与顺序

1. **恢复非默认排序下的编辑入口。** 保留上移 / 下移只在默认顺序显示；编辑、删除和行内编辑在默认与非默认排序下都可用。扩展清单与 Tree Item context 值同步调整，并覆盖默认顺序、收益率排序和金额排序三种状态。
2. **统一港币折算口径。** 持仓悬浮卡与管理页的现价、平均成本继续使用 HKD；市值、浮动盈亏、当日盈亏、成本金额及按币种小计按当前汇率显示 CNY。界面明确标注原币种单价与折算金额，避免把折算后的单价误认为券商价格。
3. **让汇率来源可见。** 持仓总计行显示当前折算汇率；汇率等于默认 `0.9` 时明确标记为「默认」，提醒它不是自动获取的实际汇率。关闭折算时继续显示未合并说明，不恢复币种分组。
4. **补齐停牌展示。** 普通行情悬浮卡、Stock/Fund/Futures Tree View、状态栏行情模式与持仓模式统一优先显示停牌图标和「停牌」；停牌期间不把当日零变动当作“平盘”，复牌后恢复开市、休市或过期状态。
5. **归一化手动配置。** 汇率只接受有限数值 `0.1–2` 或 `null`，其他值安全回退到默认 `0.9`；`treeViewFields` 按字段合并默认值、转成 boolean 并至少保留一项，扩展激活与配置变更使用同一读取函数。
6. **补两个轻量管理体验。** 有未保存草稿时在编辑器页签标题显示明确标记；在管理页内按 `Ctrl+S` 使用与「保存全部」相同的有效性、保存中和重复提交保护。不改变现有保存事务和关闭确认流程。
7. **同步说明与发布验收。** 更新 README、架构文档、发布清单和产品记录，补纯函数、Tree Item、页面消息与状态栏回归；版本号、README 版本声明和 CHANGELOG 在发布准备阶段统一为 `0.8.4`。
